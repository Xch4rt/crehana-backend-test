<interfaces>
Measured facts (07-RESEARCH.md §Clean-Clone Rehearsal, §Delivery, §Environment Availability). Take
them as given.

**The five traps, all measured:**
1. **Port collision.** The developer stack is up: `test-api-1` on `0.0.0.0:8000`, `test-db-1` on
   `0.0.0.0:5432`. Ports are hard-coded in `docker-compose.yml` and there is deliberately no override
   file (D-16). The rehearsal must `docker compose down` the dev stack (keeping its volume) as step 1.
2. **Project/volume collision.** Compose derives the project name from the directory basename; the
   repo dir is `test`, so the dev project is `test` with volume `test_pgdata`. Set
   `COMPOSE_PROJECT_NAME=crehana-rehearsal` explicitly anyway, so the isolation is stated rather than
   inherited — then the clone's `docker compose down -v` cannot touch the dev database.
3. **`.env` bootstrap.** `docker-compose.yml` declares `env_file: .env` on both `api` and `test`, and
   compose *requires* it; `.env` is git-ignored, so the clone has none. `make env` → `sh scripts/init-env.sh`
   needs only POSIX sh, awk, cp, mv and `openssl` or `/dev/urandom` — no Python, no `.venv`, no Docker.
   It is therefore necessarily the first extracted command. Assert `.env` exists afterwards and that
   its `JWT_SECRET` does **not** begin `replace-me` (ADR-084 refuses that value at boot).
4. **`make` targets that need `.venv`.** `install format lint typecheck arch test test-unit run
   break-check` all invoke `$(VENV)/bin/…`; `env up down docker-test` do not. A rehearsal on a machine
   with no `.venv` proves the README's Docker path names only the second set.
5. **Rehearsing the wrong tree.** Refuse to start when `git status --porcelain` is non-empty — the same
   refusal `break-check.sh` already implements. A clone proves the committed state, so a dirty tree
   makes the result a lie.

**Other measured facts:**
- `api` reaches `healthy` after about three polls at 3s intervals once the image is built; the
  `--no-cache` build is the long pole. A fresh project volume is empty, so
  `docker/initdb/01-create-test-database.sql` runs and `taskmanager_test` exists — which is what makes
  `make docker-test` work in the clone. On a reused volume it would not; hence `down -v`.
- `make up` runs in the **foreground** by design. The script backgrounds it with output tee'd to a log
  and polls `docker compose ps` for `api healthy`, which is what an evaluator does with a second
  terminal.
- **`timeout(1) does not exist on this macOS host.`** Every bounded wait is a POSIX polling loop with
  `sleep` and a counter — the idiom `docker/entrypoint.sh` already uses. Do not write `timeout`.
- `/bin/sh` is dash in the Debian image, and `break-check.sh` traps `HUP INT QUIT TERM` explicitly
  because a shell killed by an untrapped signal does not run its EXIT trap under dash (ADR-094).
- `git clone "$PWD" <dest>` clones the local repository's current branch and history — sufficient.
- Delivery: remote `git@github.com:Xch4rt/crehana-backend-test.git`; visibility **already PUBLIC** (no
  flip needed); default branch `main` local and remote; **332 commits, 289 unpushed** (`origin/main`
  is at `f879894`, Phase 1); 3 CI runs observed, all success, all on Phase 1 commits — **Phases 2-6
  have never run on a runner**; 100% conventional-commit subjects; **zero** AI attribution trailers in
  any of the 332 commits.
- Risks on the first push, assessed: the CI `JWT_SECRET` is safe (41 chars, not `replace-me`), the test
  DSN resolves to the service container's `taskmanager_test`, `git` and the break-check identity are
  fine on an Ubuntu runner, `dash` is handled by ADR-094, `pip install -e .` runs before the gates.
  The one genuinely unobservable-until-pushed risk is `filterwarnings = error` divergence between the
  3.14 host and CI's 3.13 — mitigated in advance because `make docker-test` runs the same suite on
  3.13.
- 06-04 handed Phase 7 one number to take: **the CI leg of D-11's three-way coverage agreement**.
  Its prediction of 1796 statements is **stale** (it predates 06-05; the host now reports 1659). Read
  the total out of the run log and record what CI actually prints (Pitfall 7).
- The rehearsal is a **spot check, not a gate** — the `break-check.sh` precedent (D-09): deliberately
  in neither `.pre-commit-config.yaml` nor `.github/workflows/ci.yml`, so CLAUDE.md's two-places rule
  is satisfied by saying so rather than by adding two entries.
- Orchestrator decision on Q8: the rehearsal **leaves the developer stack down** and prints the one
  command that restores it. Predictable beats friendly.
- `.planning/` is tracked (227 files) and is not in the Docker build context, but it **is** in the
  clone — which is what lets the script check the README's `[PDF x.y]` keys against
  `.planning/REQUIREMENTS.md`.
