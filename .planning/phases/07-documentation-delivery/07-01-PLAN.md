- **Three of the four obvious spellings publish a lie.** `{"model": M}` publishes
  `application/json`; adding an empty `content` block publishes both media types, one of them
  schema-less; `{"model": M, "content": {...$ref...}}` publishes both with the schema. Only the
  **no-`model`** form is correct:
  `{"description": d, "content": {"application/problem+json": {"schema": {"$ref": "#/components/schemas/Problem"}}}}`.
- Without a `model` key FastAPI never registers the component, so the `$ref` dangles. The verified
  fix is a `FastAPI` subclass overriding `openapi()` and `setdefault`-ing the component;
  `super().openapi()` caches into `self.openapi_schema` and returns the same object, so the call is
  idempotent. Prefer the subclass to `app.openapi = fn`, which `mypy --strict` rejects as
  `method-assign`.
- Each router module already defines module-level `Final[str]` description constants
  (`UNAUTHENTICATED_DESCRIPTION`, `NOT_FOUND_DESCRIPTION`, `DUPLICATE_NAME_DESCRIPTION`,
  `VALIDATION_DESCRIPTION`, `UNEXPECTED_DESCRIPTION`, and siblings) and spreads them into
  `responses={401: {"description": ...}, ...}`. The change is mechanical at every site.
- The server's body shape, from `presentation/api/errors/problem.py`: `type`, `title`, `status`,
  `detail`, `instance`, `code`, then `errors` **only when truthy**. `errors` has two real shapes —
  a domain `details` dict (`dict[str, str | int | float | bool | None]`, e.g.
  `{"from": "completed", "to": "pending"}`) and the 422 list of

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server → published document | `/openapi.json` is what a client generates code from; a document that disagrees with the wire is worse than no document |
| error body → client | The problem document carries `detail`, `code` and `errors` to an untrusted caller |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Spoofing | The published error media type | mitigate | Task 2 uses the no-`model` form and task 3 asserts no non-2xx leg outside `/health` 503 mentions `application/json`; a document that advertises a media type the API never serves misleads every generated client |
| T-07-02 | Information disclosure | `ProblemResponse.errors` in the published schema | mitigate | The model declares only the two shapes the server already emits — the domain `details` dict and the 422 `{field, message, type}` list built by `handle_validation_error`, which deliberately drops Pydantic's `input`, `ctx` and `url` (D-07). The schema documents no member the server does not already send, so it discloses nothing new |
| T-07-03 | Tampering | A later route arriving with an undocumented refusal leg | mitigate | `tests/architecture/test_openapi_completeness.py` is a totality gate with set equality on tags and a failing (never skipping) non-vacuity guard |
| T-07-SC | Tampering | npm/pip/cargo installs | accept | This plan installs nothing; `requirements*.txt` is untouched, so the Package Legitimacy Gate has no subject |
