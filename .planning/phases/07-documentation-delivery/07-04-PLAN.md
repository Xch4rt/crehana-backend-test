## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| documentation → evaluator | The README is the first and possibly only file read; a command in it that does not work costs the whole submission |
| repository root → Docker build context | The `test` stage's file set decides what a gate can read in the container and in CI |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-11 | Information disclosure | Secrets in README examples | mitigate | The quickstart uses `make env` and never prints, pastes or invents a `JWT_SECRET`; the only value the repository publishes is `.env.example`'s placeholder, which ADR-084 refuses at boot. The example account uses a throwaway address and an obviously fake password, and no bearer token from a real run is pasted into the file |
| T-07-12 | Spoofing | A README quickstart that talks to something other than the documented stack | mitigate | The commands are the ones executed live against the container, and `curl -s localhost:8000/health` returning the `version` field is the first step, so a reader learns immediately which process answered |
| T-07-13 | Tampering | Documentation drifting from the code | mitigate | `tests/architecture/test_documentation_claims.py` with set equality on the endpoint table, id resolution for every ADR citation, a `.PHONY` check for every `make` target, and a non-vacuity test that fails rather than skips |
| T-07-14 | Denial of service | A gate green on the host and red in CI | mitigate | The `COPY` line lands in the same task, and that task's verification command is `make docker-test` |
| T-07-SC | Tampering | npm/pip/cargo installs | accept | No dependency is added; the gate uses stdlib parsing and the application factory |
