<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated internet → `GET /health` | The only route in this phase, and it is deliberately open (D-08) |
| infrastructure failure → HTTP response body | A database outage must be reported without describing the database |
| request → transaction | `get_uow` is where a request acquires the ability to write |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-26 | Information disclosure | `/health` body | mitigate | The probe returns a bool; the exception is caught and discarded, and the body is a fixed three-member document. `test_the_unavailable_body_leaks_no_driver_detail` asserts the response contains no `psycopg`, `Traceback`, `password` or host string |
| T-3-27 | Information disclosure | `/health` reachability | accept | The endpoint is unauthenticated by D-08 and must stay so in Phase 5; it reveals only liveness, a coarse `ok`/`unavailable` flag and the application version, which is already public in the OpenAPI document |
| T-3-28 | Denial of service | `/health` database probe | mitigate | `asyncio.timeout(2.0)` bounds every probe, so a hung database cannot pile up request-scoped connections; `pool_pre_ping=True` avoids reusing dead ones |
| T-3-21 | Repudiation / integrity | `get_uow` teardown | mitigate | The dependency never commits (Anti-Pattern 1), and `test_the_dependency_does_not_commit_on_teardown` proves it with a second connection |
| T-3-29 | Tampering | startup side effects | mitigate | D-06: no migration and no `SELECT` runs in `create_app()` or the lifespan startup, so building the app cannot mutate a database and replicas cannot race |
| T-3-25 | Information disclosure | engine disposal | mitigate | The lifespan disposes the engine on shutdown, so pooled connections carrying credentials are not left open after the process is asked to stop |
| T-3-SC | Tampering | pip installs | accept | No package is installed |
</threat_model>
