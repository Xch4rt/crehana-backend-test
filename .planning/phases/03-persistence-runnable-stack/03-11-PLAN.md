      3. **`test_database_url` is a field on the production `Settings` object.** Context: the
         `.env.example` parity gate is an exact set equality and `extra="forbid"` makes an
         undeclared `.env` key a boot failure. Options: the three from RESEARCH Pitfall 6.
         Decision: option (a). Consequences: a test-only key lives on the production settings
         object, defaulting to `None`; `cp .env.example .env && docker compose up` keeps working
         and the parity gate was not weakened.
      4. **WR-05: a naive datetime from the database is an infrastructure fault.** Context: the
         Phase 2 review deferred whether the mapper or the domain owns that failure. Decision:
         D-14 is refined by *scope*, not by error type — a naive datetime reaching the domain
         remains a `ValidationError`, and the mapper additionally refuses one read from the
         database, raising `NaiveDatetimeFromDatabaseError` (a `RuntimeError`, deliberately not a
         `DomainError`). Consequences: a schema regression away from `timestamptz` surfaces as a
         500 rather than as a validation problem blamed on the caller; five existing domain tests
         and the HTTP contract are unchanged. This ADR explicitly refines the Phase 2 D-14 ADR —
         name it.
      5. **The entrypoint's readiness probe lives in a shell heredoc, not in `src/`.** Context:
         RESEARCH Open Question 1. Decision: heredoc. Consequences: the retry bound is not unit
         tested; it is proven by the cold-start rehearsal (evidence `03-10-cold-start.txt`), and
         the module never enters the coverage denominator, which has no `omit` and no
         `pragma: no cover`.
      6. **The migrations directory is `migrations/`, not `alembic/`.** Context: `.flake8` already
         excluded `migrations`. Consequences: no dead configuration line, and `alembic.ini`, the
         `.flake8` exclusion and the Dockerfile `COPY` lines all name the same directory.
      7. **One runtime version string.** Context: three copies existed and RESEARCH wanted a
         fourth. Decision: `taskmanager.__version__`, bound to `pyproject.toml` by
         `tests/unit/test_version.py`. Options considered: `importlib.metadata.version`, rejected
         because `pytest.ini`'s `pythonpath = src` exists precisely so a bare checkout works.
      8. **The engine is built in the composition root and disposed in the lifespan.** Context:
         STACK.md sketched a module-level engine, ARCHITECTURE.md Anti-Pattern 10 forbids one.
         Consequences: `create_app()` stays constructible with a fake DSN and no database, which
         `tests/conftest.py` already depended on; `app.state` carries one typed
         `DatabaseResources` so `dependencies.py` needs exactly one `cast`.
      9. **Migrations run in the container entrypoint, never in the app.** D-06. Consequences:
         importing the app has no database side effect; replicas cannot race; the `test` image
         stage does not migrate, because the pytest fixture owns the test schema.
      10. **Follow-up to ADR-017 and ADR-018.** The `make up` / `make down` placeholders were
          replaced as promised and the Dockerfile `test` stage now runs through
          `docker compose run --rm --build test`. State that both promises were kept and name the
          plan that kept them.
      11. **PostgreSQL 5432 is published on the host.** Context: D-15 needs it so host-side
          `make test` reaches the same container. Decision: accept, with obviously-fake
          throwaway credentials identical to CI's. Consequences: an honest sentence rather than
          silence, and nothing in the repository carries a real credential.
      12. **No pagination on task listing in this phase.** Context: the brief does not ask for it
          and the per-list scope bounds the work. Decision: out of scope; recorded so a reviewer
          reads it as a decision rather than an omission.
