<!-- The contract, verbatim from src/taskmanager/application/ports/repositories.py L35-L57. -->

```python
class TaskRepository(Protocol):
    async def get(self, task_id: UUID) -> Task | None: ...
    async def add(self, task: Task) -> None: ...
    async def update(self, task: Task) -> None: ...
    async def delete(self, task_id: UUID) -> None: ...
    async def list_for_task_list(
        self,
        task_list_id: UUID,
        *,
        status: TaskStatus | None = None,
        priority: TaskPriority | None = None,
    ) -> Sequence[Task]: ...
    async def completion_stats(self, task_list_id: UUID) -> CompletionStats: ...
```

CompletionStats lives at src/taskmanager/domain/value_objects/completion.py and is constructed
as `CompletionStats(total=..., completed=...)`; it computes the percentage itself.

Verified aggregate SQL (03-RESEARCH.md §"Pattern 4"):
```python
select(
    func.count().label("total"),
    func.count().filter(TaskRow.status == TaskStatus.COMPLETED.value).label("completed"),
).where(TaskRow.task_list_id == task_list_id)
# -> SELECT count(*) AS total, count(*) FILTER (WHERE tasks.status = %(status_1)s) AS completed
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller-supplied filter values → SQL | `status` and `priority` arrive from an HTTP query string in Phase 4; this adapter decides how they reach the database |
| aggregate result → business number | The completion percentage is a user-visible claim; a wrong aggregate is a correctness failure, not a display bug |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-17 | Tampering | `list_for_task_list` filters | mitigate | Filters are appended as `.where(Column == value)` with bound parameters and the value is always an enum member's `.value`, so a hostile query-string value cannot reach SQL as text. This is the exact spot RESEARCH names as the tempting place to f-string a filter |
| T-3-20 | Elevation of privilege | cross-list reads | mitigate | Every statement is scoped by `task_list_id` in SQL, and `test_listing_never_returns_a_task_from_another_list` asserts it, so Phase 4 cannot accidentally serve another list's tasks (ASVS V4, ADR-008) |
| T-3-14 | Information disclosure | CHECK violations | mitigate | Deliberately untranslated, so they reach Phase 2's catch-all and become the fixed 500 body with no message — the constraint name never reaches the client |
| T-3-22 | Denial of service | unbounded listing | accept | Pagination is out of scope for this phase and is not in the brief; the per-list scope plus the `ix_tasks_task_list_id` index bounds the work per request, and the ADR in plan 03-11 records the omission honestly |
| T-3-21 | Repudiation / integrity | uncommitted writes | mitigate | The widened SC-4 gate now scans `tasks.py` too |
| T-3-SC | Tampering | pip installs | accept | No package is installed |
</threat_model>
