# Phase 3 Plan 01: Declarative Base, Constraint Names and the Three ORM Rows Summary

**The persistence schema now exists as SQLAlchemy 2.0 declarative rows whose twelve D-12 constraint names are *generated* by a `MetaData` naming convention rather than typed anywhere twice, proven by nine tests that compile the PostgreSQL DDL and assert on it without a database - and the case-sensitivity contradiction PATTERNS.md flagged is settled in the same plan, so the model, the entity docstring and the in-memory fake now describe one rule instead of two.**

## Accomplishments

- **The constraint names are derived, not transcribed.** `NAMING_CONVENTION` in `base.py` carries the five keys from RESEARCH Pattern 2, and the compiled DDL renders `pk_users`, `pk_task_lists`, `pk_tasks`, `uq_task_lists_owner_id_name`, `fk_task_lists_owner_id_users`, `fk_tasks_task_list_id_task_lists`, `fk_tasks_assignee_id_users`, `ck_tasks_status`, `ck_tasks_priority`, `ck_tasks_completed_at_matches_status` and `ix_tasks_task_list_id` without any of them appearing in a `__table_args__` entry. `models.py` names exactly one constraint explicitly - `uq_users_email_lower` - because an expression index has no `column_0_N_name` to interpolate, and even that one is read from the constant rather than retyped.
- **Twelve `Final` constants are the single source D-13 will key on.** `constraints.py` contains names and nothing else, and its docstring states the failure mode in the terms that matter: a rename applied to the schema but not here does not fail a type check or a lint run, it silently stops matching `diag.constraint_name`, and LIST-06's 409 quietly becomes a 500.
- **The schema is proven against rendered SQL, not against intentions.** `tests/unit/infrastructure/test_models.py` compiles `CreateTable` plus `CreateIndex` for the three tables against the psycopg dialect and asserts: every constant appears; `CONSTRAINT uq_task_lists_owner_id_name UNIQUE (owner_id, name)` with no case-folding expression; `status VARCHAR(16)` / `priority VARCHAR(16)` with both CHECK value lists and no `CREATE TYPE`; all eight timestamp columns `timezone is True` and no `TIMESTAMP WITHOUT TIME ZONE` anywhere; `ON DELETE CASCADE` on both DB-05 foreign keys and `ON DELETE SET NULL` on `tasks.assignee_id`; no column with a database-side default; every `String(n)` equal to the entity `ClassVar` it mirrors; and the single relationship at `lazy="raise"`.
- **DB-03 is asserted at its bluntest.** A ninth test (beyond the eight the plan enumerates) checks that `{UserRow, TaskListRow, TaskRow}` is disjoint from `{User, TaskList, Task}` and that `UserRow` is not a subclass of `User`. Every other test in the file would pass unchanged if the entities themselves had been mapped imperatively - which is precisely the shape DB-03 rules out - so the claim needed its own test.
- **The case-sensitivity contradiction is gone, and a test keeps it gone.** `FakeTaskListRepository.exists_with_name` now compares `task_list.name == name.strip()`; `task_list.py`'s module docstring names `(owner_id, name)` and explains why it differs from the users index; `tests/unit/application/test_fakes.py` pins `Groceries` ≠ `groceries`, `Groceries` == `"  Groceries  "`, and scoping by owner. `grep -rn "lower(name)" src tests` is empty and `grep -n casefold tests/unit/application/fakes.py` is empty.
- **Every vacuity guard is a count, not a truthiness check.** 12 constants, 8 timestamp columns, 22 columns, exactly `["tasks"]` as the relationship key list. A renamed table or a dropped column changes a number and fails the test rather than shrinking a list that still passes.
- **All four gates green, zero warnings, coverage back at 100%.** `make lint && make typecheck && make arch && make test`: black and isort clean over 66 files, flake8 clean, mypy strict clean over 66 source files, three import-linter contracts KEPT, **162 passed, 100.00% total coverage** under `filterwarnings = error` - so no SQLAlchemy 1.x idiom or deprecation slipped in.

## Decisions Made

- **D-12 wins over the two stale comments, and the contrast is written down.** `uq_task_lists_owner_id_name` is a plain `UNIQUE (owner_id, name)`. The reasoning that makes this non-arbitrary: `User.__post_init__` lowercases the address before it is ever stored, so `uq_users_email_lower` defends a rule the entity already enforces and can never reject a value the domain accepts. `TaskList` performs no case folding, so a case-insensitive index there would refuse `alpha` for an owner who already has `Alpha` - a rejection the domain has no concept of. The two indexes differ because the two entities differ, and that sentence is now in the entity docstring, the model comment and the fake comment.
- **D-10 is corrected here rather than patched later.** `users.updated_at` and `task_lists.description` exist on the entities and therefore exist in the baseline. The alternative - shipping D-10 literally and adding a second revision in Phase 5 - would have produced exactly the fake versioning artifact the phase context rejects, and would have left the mappers unable to round-trip until then.
- **One relationship, not zero.** RESEARCH Pattern 2 observes that the honest answer may be no relationship at all, since repositories return domain entities and explicit `select()` covers every query. `TaskListRow.tasks` is declared anyway, for one reason: DB-03 and roadmap SC-2 make a claim about `lazy="raise"`, and a claim about a set with no members is not worth asserting. `passive_deletes=True` accompanies it so SQLAlchemy does not try to load the children it has just been told to refuse, on a delete PostgreSQL will cascade itself.
- **The naming-convention test renders indexes too.** The plan excludes `IX_TASKS_TASK_LIST_ID` from the expected set, which is correct if only `CreateTable` is compiled - `CREATE INDEX` is a separate statement, and so is the `uq_users_email_lower` expression index. Compiling `CreateIndex` for each table's indexes puts all twelve names in scope and makes the assertion a strict superset of the plan's, with `len(D12_CONSTRAINT_NAMES) == 12` as the guard. Recorded as deviation 1 below.
- **`create_engine("postgresql+psycopg://").dialect`, not `postgresql.dialect()`.** mypy strict rejects the latter with `no-untyped-call`, and this repository has no `# type: ignore` in `src/` or `tests/` and is not starting now. `create_engine` resolves the dialect and the DBAPI eagerly but connects lazily, so the unit test still needs no PostgreSQL - and it compiles against the exact dialect the application will run on. Recorded as deviation 2 below.
- **Forbidden forms are described, not spelled.** The plan's own acceptance greps require `server_default` and `lower(name)` to be absent from files whose prose the plan also asks to explain why those forms are absent. The 01-04 Makefile precedent resolves it: state the rule in words, keep the literal out, and let the test prove the absence. The one place the literal was genuinely needed - asserting the DDL does *not* contain a case-folded name index - now builds both halves of the contrast from a single `CASE_FOLDED_INDEX = "lower(%s)"` template, which is also the better test. Recorded as deviation 3 below.
- **No requirement ticks taken.** DB-01, DB-03, DB-04 and DB-05 are all claimed again by `03-11-PLAN.md`, the phase-close plan. Under the last-claimant convention this project has followed since 02-01, 03-11 owns all four ticks; ticking them here would make `REQUIREMENTS.md` claim a complete requirement while ten plans of the phase are still unwritten.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical] The naming-convention test asserted eleven of twelve names**

- **Found during:** Task 2
- **Issue:** The plan specifies that every constant *except* `IX_TASKS_TASK_LIST_ID` must appear in the concatenated DDL of the three tables. That exclusion is right only for `CreateTable`-only rendering - but the same reasoning silently excludes `UQ_USERS_EMAIL_LOWER`, which is also an index and also absent from `CREATE TABLE users`. Following the plan literally would have produced a test that never checked the one name `models.py` types by hand, which is precisely the name most exposed to a typo.
- **Fix:** `_ddl()` compiles `CreateTable` **and** a `CreateIndex` for each of the table's indexes, so the concatenated schema DDL contains all twelve names and the test asserts the full set with `len(D12_CONSTRAINT_NAMES) == 12` as its vacuity guard.
- **Files modified:** `tests/unit/infrastructure/test_models.py`
- **Verification:** `missing == []` over all twelve constants; the test was observed failing during development when the index statements were not yet rendered.
- **Committed in:** `b8bfe4e` (Task 2 commit)

**2. [Rule 3 - Blocking] `postgresql.dialect()` is an untyped call under mypy strict**

- **Found during:** Task 2
- **Issue:** The plan's verify command and acceptance criteria use `sqlalchemy.dialects.postgresql.dialect()`. It runs fine from a shell, but `make typecheck` fails with `Call to untyped function (unknown) in typed context [no-untyped-call]` - SQLAlchemy's dialect classes carry no annotated `__init__`. `PGDialect()` was tried and fails identically. The only escapes would have been a `# type: ignore` (the first in this repository) or dropping mypy over `tests/`, both unacceptable.
- **Fix:** `DIALECT: Final[Dialect] = create_engine("postgresql+psycopg://").dialect`, with a comment stating that `create_engine` connects lazily so no database is required, and naming the rejected shorter form and why. `create_engine` is fully annotated.
- **Files modified:** `tests/unit/infrastructure/test_models.py`
- **Verification:** `mypy src tests` clean over 66 files; the rendered DDL is byte-identical to the `postgresql.dialect()` output (checked before and after the change); the plan's own `python -c` acceptance commands still pass unchanged, since they run outside mypy.
- **Committed in:** `b8bfe4e` (Task 2 commit)

**3. [Rule 1 - Bug] Two acceptance greps contradicted the prose the same plan asked for**

- **Found during:** Task 2 and Task 3
- **Issue:** `grep -rn "declarative_base()\|Column(\|server_default" models.py` must print nothing, but the plan's action text asks the module docstring to explain that no column carries a `server_default` - and the word alone tripped the gate. The same collision recurred in Task 3: `grep -rn "lower(name)" src tests` must print nothing, yet Task 2's action text asks the test to assert the DDL does not contain `lower(name)`, and the model and fake comments were written to name the rejected form. Left as-is, three artifacts would have failed two gates the plan lists as acceptance criteria.
- **Fix:** The 01-04 Makefile convention was applied - describe the forbidden form without spelling it. The models docstring now says "no column below delegates its value to a server-side default" and states explicitly that the keyword is kept out so the grep gate can stay strict; the model and fake comments say "a case-folding expression index"; and the test builds both halves of the case contrast from one `CASE_FOLDED_INDEX = "lower(%s)"` template, used positively for `email` and negatively for `name`.
- **Files modified:** `src/taskmanager/infrastructure/db/models.py`, `tests/unit/application/fakes.py`, `tests/unit/infrastructure/test_models.py`
- **Verification:** both greps now exit 1 with no output; `test_no_column_declares_a_server_default` and `test_the_task_list_name_unique_constraint_is_case_sensitive` still pass, and the template form makes the second one assert *both* directions of the contrast in the same test.
- **Committed in:** `b8bfe4e` and `1b3b65e`
