```python
class UnitOfWork(Protocol):
    task_lists: TaskListRepository
    tasks: TaskRepository
    users: UserRepository

    async def __aenter__(self) -> Self: ...
    async def __aexit__(self, exc_type, exc, tb) -> None: ...
    async def commit(self) -> None: ...
    async def rollback(self) -> None: ...
```

Normative obligations recorded in that module's docstring: `__aexit__` MUST roll back whatever
`commit()` did not make durable, on every exit path, and MUST return `None` so an exception
leaving the block is never swallowed.

Constructor type decided by RESEARCH Pattern 3: `Callable[[], AsyncSession]`, not
`async_sessionmaker[AsyncSession]` — an `async_sessionmaker` satisfies the callable type, and the
D-01 fixture can hand in a plain closure returning a connection-bound session without a `cast`.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| use case → transaction | The decision to make a write durable crosses here; anything that commits implicitly removes that decision from the caller |
| pooled session → next request | A session handed back dirty leaks state, and with `expire_on_commit=False` the next holder inherits it |
| test transaction → durable storage | The savepoint join mode is what keeps a committing test from writing to disk |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-21 | Repudiation / integrity | `__aexit__` | mitigate | Rollback on every exit path that did not commit (WR-06), proven by `test_an_uncommitted_block_is_rolled_back`; `__aexit__` returns `None`, so a failing use case can never answer 200 |
| T-3-23 | Tampering | partial writes on failure | mitigate | `test_a_domain_error_leaves_nothing_written` asserts atomicity across a multi-repository block, so a business rejection cannot leave half a change behind |
| T-3-24 | Information disclosure | dirty pooled session | mitigate | `__aexit__` closes the session in a `finally`; `expire_on_commit=False` is paired with that close so no request inherits another's identity map |
| T-3-19 | Denial of service / integrity | test residue | mitigate | The falsification check proves the savepoint join mode is really in effect (Pitfall 1), and the suite leaves `users` empty |
| T-3-25 | Information disclosure | engine construction | mitigate | `create_engine` never logs the DSN and `echo` is left off, so a credential cannot reach stdout through SQLAlchemy's logger |
| T-3-SC | Tampering | pip installs | accept | No package is installed |
</threat_model>
