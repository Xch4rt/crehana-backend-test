<objective>
Create the SQLAlchemy 2.0 declarative layer: a `Base` whose `MetaData` naming convention
*generates* the D-12 constraint names, a `constraints.py` that is the single source of those
names for the migration and the repository error translation, and the three ORM row classes
that mirror the three domain entities field for field.

This plan also settles the first of the three PATTERNS.md discrepancies: per-owner task-list
name uniqueness is **case-sensitive** (`UNIQUE (owner_id, name)`) per locked decision D-12, and
the in-memory fake plus the entity docstring are corrected to say the same thing in the same
commit.

Purpose: every later artifact in this phase — the baseline migration, the mappers, the
repositories' `IntegrityError` translation and every integration test — is written against
these tables and these names. Getting the names right here means they are never typed twice.
Output: `infrastructure/db/{base,constraints,models}.py`, a unit test that proves the rendered
DDL, and a reconciled case-sensitivity story.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| application → database | Entity field values become SQL parameters; column caps and CHECK constraints are the last line of defence before storage |
| schema definition → migration → repository error translation | A constraint name is a contract shared by three artifacts; a mismatch turns a business conflict into a server fault |
