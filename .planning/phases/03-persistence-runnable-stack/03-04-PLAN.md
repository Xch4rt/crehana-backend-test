<objective>
Write the two pure modules the repository adapters are built from: the explicit ORM ↔ entity
mappers (DB-03, research Pattern 5) and the `IntegrityError` inspection that D-13's error
translation keys on.

This plan also settles the Phase 2 review's deferred WR-05 question in code: a naive datetime
read back from the database is an **infrastructure** fault raised by the mapper before an entity
is constructed, not a domain `ValidationError`. D-14 is refined by scope, not overturned — a
naive datetime reaching the domain is still a `ValidationError`; the mapper simply never lets
one get that far.

Purpose: both modules are pure functions, so they are unit-testable with no database, which is
where this phase's cheap coverage comes from. Every repository in plans 03-06 and 03-07 calls
them.
Output: `infrastructure/db/mappers.py`, `infrastructure/db/errors.py` and their two unit suites.
</objective>

ORM rows (plan 03-01): UserRow, TaskListRow, TaskRow — same column names as the entity fields,

Domain error alias (src/taskmanager/domain/exceptions.py L38-39):
```python
DetailValue = str | int | float | bool | None
Details = dict[str, DetailValue]
```

isinstance narrowing before `.diag` is reachable (no `type: ignore` shortcut exists).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| database rows → domain entities | Values that left the process come back in; the mapper is the only place to check them before they become entities |
| psycopg/SQLAlchemy exceptions → application layer | A raw driver exception carries SQL text and column values; it must be converted or re-raised, never forwarded |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-13 | Information disclosure | `errors.py` | mitigate | `violated_constraint()` returns only the constraint *name* and nothing else; the SQL statement and bound parameters carried by `IntegrityError` are never read, logged or attached to a `DomainError`. Callers put only business values into `Details`, whose alias forbids arbitrary objects |
| T-3-14 | Information disclosure | unrecognised `IntegrityError` | mitigate | D-13 re-raise: the exception reaches Phase 2's catch-all handler, which emits the fixed 500 body with no message — proven already by `tests/api/test_error_contract.py` |
| T-3-15 | Tampering | `*_to_entity` enum rebuild | mitigate | `TaskStatus(row.status)` re-validates the stored string, so a value that somehow bypassed `ck_tasks_status` cannot become a live entity state |
| T-3-16 | Spoofing / integrity | naive timestamps | mitigate | `_aware()` refuses any naive datetime read from the database, so an ordering or expiry decision can never be made on an ambiguous instant (WR-05) |
| T-3-SC | Tampering | pip installs | accept | No package is installed; `psycopg` and `sqlalchemy` were already pinned and audited |
</threat_model>
