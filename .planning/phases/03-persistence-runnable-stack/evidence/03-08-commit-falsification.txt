RED/GREEN evidence for the commit proof (plan 03-08, task 3).

The whole suite in tests/integration/test_unit_of_work.py reads back what it
wrote over the SAME connection the fixture owns, so a `commit()` that had
silently become a no-op would leave every one of those reads green. That is
RESEARCH Pitfall 1: `join_transaction_mode` defaults to
`conditional_savepoint`, which degrades to `rollback_only` for exactly the
connection shape the `connection` fixture produces, and under that degradation
the unit of work's commit does nothing at all.

The check below is therefore the one that says the commit is load-bearing. One
line was commented out in `test_a_successful_block_commits_once`, the test was
run, the line was restored, and the whole module was run again. Nothing else
changed between the two runs.

The test goes red, which means the write really was undone by __aexit__'s
rollback when nothing committed - and so the green run is green because the
commit happened, not because the savepoint mode silently swallowed it.
