```python
    async def execute(self, command: ListTasksCommand) -> TaskCollectionResult:
        async with self._uow:
            await visible_task_list(self._uow, command.task_list_id, command.actor_id)
            tasks = await self._uow.tasks.list_for_task_list(
                command.task_list_id,
                status=command.status,
                priority=command.priority,
            )
            # ADR-009: no filter argument here, on purpose.
            stats = await self._uow.tasks.completion_stats(command.task_list_id)
        return TaskCollectionResult.from_parts(tasks, stats)
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `{list_id}` / `{task_id}` path pair → visibility | Two caller-supplied identifiers, whose relationship is itself a rule (D-14) |
| filter arguments → SQL | `status` and `priority` reach the repository as typed enum members, never as text |
| command → domain mutator | Which mutators are reachable is what defines the writable surface |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-4-28 | Elevation of privilege | a task addressed under a list it does not belong to | mitigate | Every verb loads through `visible_task`, which compares `task.task_list_id` with the path's list before anything else; one unit test per verb asserts the refusal is byte-identical to the absent-task refusal (D-14, TASK-02) |
| T-4-29 | Elevation of privilege | cross-tenant read, update or delete of a task | mitigate | `visible_task` also checks the parent list's owner; two-actor tests per verb assert `TaskNotFoundError` and explicitly `not isinstance(error, AuthorizationError)` (D-04) |
| T-4-30 | Elevation of privilege | mass assignment of `status` through the generic PATCH | mitigate | `UpdateTaskCommand` declares no `status`; the use case calls no status mutator; `grep -c "change_status"` printing `0` is an acceptance criterion, and the schema's `extra="forbid"` (plan 04-07) makes the attempt a 422 |
| T-4-31 | Tampering | SQL injection through a filter value | mitigate | Filters travel as `TaskStatus` / `TaskPriority` members to `list_for_task_list`, which binds `.value` as a parameter (proved in 03-07); the use case never builds a predicate from text |
| T-4-32 | Information disclosure | a wrong completion percentage caused by the filter | mitigate | `completion_stats` is called with the list id alone; a regex acceptance criterion asserts no filter argument appears in that call, and `test_the_filter_never_moves_the_statistics` asserts the behaviour |
| T-4-33 | Denial of service | an overdue task becoming permanently unpatchable | mitigate | D-07: `reschedule` runs only when `due_date` was provided, proved by `test_a_patch_without_due_date_does_not_recheck_an_overdue_task` |
| T-4-34 | Repudiation | a refused write that still commits | mitigate | Every failure test asserts `commits == 0` and `rollbacks == 1` |
| T-4-SC | Tampering | npm/pip/cargo installs | accept | This plan installs no package |
</threat_model>
