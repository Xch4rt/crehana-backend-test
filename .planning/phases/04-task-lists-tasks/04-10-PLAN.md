<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| nested path segments → visibility | `{list_id}` and `{task_id}` together define what the caller may reach |
| request body → writable surface | What a PATCH accepts is the definition of what a client may change |
| request → database work | How many statements one request issues bounds what a caller can cost the server |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-4-57 | Elevation of privilege | a nested path segment honoured on one verb and ignored on another | mitigate | The wrong-list 404 is asserted on GET, PATCH, DELETE **and** the status endpoint, and each body is compared with the absent-task body (D-14, TASK-02) |
| T-4-58 | Elevation of privilege | cross-tenant task access over HTTP | mitigate | One not-owned test per verb via the actor override, each asserting `task_not_found` and explicitly not `task_list_not_found` (D-04, ASVS V4) |
| T-4-59 | Elevation of privilege | mass assignment of `status` through the generic PATCH | mitigate | The 422 is asserted **and** the task is re-read to prove its status did not move — a 422 alone would not distinguish a refusal from a refusal-after-write (D-08, TASK-03) |
| T-4-60 | Tampering | a filter value reaching SQL as free text | mitigate | The invalid-filter 422 lands at `query.status` before any use case runs, proved per parameter |
| T-4-61 | Information disclosure | a wrong completion percentage presented as fact | mitigate | `test_the_statistics_cover_the_whole_list_whatever_the_filter` compares the three numbers across two responses; `test_the_envelope_has_exactly_the_four_members_d9_names` stops the envelope from growing a field that would confuse the claim |
| T-4-62 | Denial of service | N+1 amplification on either collection endpoint | mitigate | The statement recorder asserts both an exact expected count and its invariance between 1 and N rows, plus a non-vacuity guard so the assertion cannot pass by recording nothing (D-17) |
| T-4-63 | Information disclosure | an error body echoing client input | mitigate | Inherited from plan 04-09's marker-string test and the existing `test_validation_problem_never_echoes_the_client_input`; the domain 422 bodies asserted here carry only `{"field": ...}` |
| T-4-SC | Tampering | npm/pip/cargo installs | accept | This plan installs no package |
</threat_model>
