<objective>
Close the gap the researcher found in the "reference" use case, and promote its load-and-authorize
block into the one module the other ten use cases will share.

Purpose: D-11 nests the status endpoint under `{list_id}` and D-14 requires a task addressed under
the wrong list to answer 404. `ChangeTaskStatusCommand` is `(actor_id, task_id, new_status)` — it
has no `list_id` to compare, so the wrong-list request would succeed. An evaluator finds that in
one curl. Separately, ten use cases are about to repeat `get` → `None or not owner` → raise; one
copy of that rule is the difference between a forgotten 404 leg being impossible and being likely.
Output: `ChangeTaskStatusCommand.task_list_id`, the wrong-list comparison, and
`application/use_cases/access.py` with its two-actor proofs.
</objective>

```python
async def visible_task_list(uow: UnitOfWork, task_list_id: UUID, actor_id: UUID) -> TaskList: ...
async def visible_task(uow: UnitOfWork, task_list_id: UUID, task_id: UUID,
                       actor_id: UUID) -> Task: ...
```

`visible_task_list` raises `TaskListNotFoundError(task_list_id)` when the list is absent or
foreign. `visible_task` raises `TaskNotFoundError(task_id)` on **every** leg, including a missing
or foreign parent list — the deliberate asymmetry
`change_task_status.py`'s docstring already argues for.

Both helpers take an already-entered `UnitOfWork`; they never open or close the block and never
commit.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| path identifiers → visibility decision | `list_id` and `task_id` are caller-supplied UUIDs; the use case, never the router, decides what they may see (ADR-008) |
| refusal shape → existence disclosure | Which error class comes out, and what its `details` carry, is itself information |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-4-12 | Elevation of privilege | a task addressed under a list the caller owns but which is not the task's parent | mitigate | `visible_task` compares `task.task_list_id` with the path's `task_list_id` before anything else and raises `TaskNotFoundError`; two unit tests, one of which compares the refusal byte for byte with the absent-task refusal (D-14) |
| T-4-13 | Information disclosure | a different error code revealing that a foreign list exists | mitigate | Task routes raise `TaskNotFoundError` on every leg, including a missing or foreign parent; `grep -c "TaskListNotFoundError" access.py` printing `1` is an acceptance criterion, and it is the `visible_task_list` leg |
| T-4-14 | Information disclosure | a foreign identifier echoed in `details` | mitigate | `TaskNotFoundError(task_id)` carries only the id the caller already supplied; the parent list's id never reaches the body |
| T-4-15 | Elevation of privilege | the visibility rule forgotten in the eleventh use case | mitigate | One module with two named functions, called by every use case; a missing call is a visible absence in a diff rather than a missing `if` inside a body |
| T-4-16 | Repudiation | a refusal that still commits | mitigate | Every failure test asserts `commits == 0` and `rollbacks == 1`, the mirror-image assertion the existing suite established |
| T-4-SC | Tampering | npm/pip/cargo installs | accept | This plan installs no package |
</threat_model>
