What this proves: the two-connection suite fails for the reason ADR-058 exists,
and not merely because a keyword is missing. The plant keeps every signature the
fix introduced (`get_for_update`, `for_update=True`) and removes only the row
lock, so the red run below is the defect itself: the second writer did not wait,
read `in_progress`, committed `pending` and was answered with a successful
`TaskResult` - and the first writer then committed `completed` over it. A caller
was told a write was durable and it is gone. With the lock restored the same
writer waits, re-reads `completed`, and is refused with
`InvalidStatusTransitionError` (the documented 409).

What this does NOT show: the reviewer's original probe ordering (B commits
`pending` AFTER A commits `completed`, persisting the forbidden transition). With
every write path entering through the locking read that ordering can no longer be
constructed - which is the fix - so the red run necessarily shows the mirror image
of it: the same two stale validations, with the other writer's commit landing
last. The reviewer's own reproduction of the original ordering is recorded in
04-REVIEW.md under CR-01.

`test_a_read_never_waits_on_a_writer` passes in BOTH runs, and that is correct:
it asserts the property the plant does not touch.

The plant was removed immediately after the red run by restoring byte-identical
copies of both files; the green run at the bottom is the shipped tree. Captures
are verbatim apart from the trailing whitespace the pre-commit hook strips and
the scratch-directory prefix of the diff header, shortened to `fixed/`.
