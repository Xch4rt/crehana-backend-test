What this proves: the `no-http-below-presentation` contract is enforced, not
decorative. A single `from fastapi import HTTPException` placed below the
presentation layer turns the contract BROKEN, names the offending import by
module and line, and turns the pytest suite red - and only the removal of that
import turns both green again.

Why the contract exists: D-15 forbids a business layer from raising
`fastapi.HTTPException`, because a layer that raises it has built an error body
by hand and bypassed the single RFC 9457 handler ARC-07 puts in charge of every
response. This contract answers the broader module-level question for the whole
subtree below presentation; the symbol-level question - an `HTTPException`
raised inside presentation, where the import IS allowed - belongs to the AST
gate plan 04-08 adds.

Why the violation is planted TWICE, in two different layers. The plan asks only
for the first. It is not sufficient on its own, and the capture says so rather
than hiding it: in RUN 1 the planted import breaks `Application knows no web
framework or ORM` as well, because that contract already forbade `fastapi` in
`taskmanager.application`. So RUN 1 proves the new contract fires, but not that
it is worth having - the build would have gone red without it.

RUN 3 is the falsification that settles that. `infrastructure` is the layer the
new contract adds and no existing contract covers: the `layers` contract permits
`infrastructure` to import anything outside the root package, and
`domain-framework-free` and `application-framework-free` name other source
modules. And so exactly ONE contract is reported BROKEN there. Without
`no-http-below-presentation`, the same import would have been reported as four
kept contracts and a green build.

Note on the pytest runs: only `test_import_contracts_hold` fails.
`test_every_contract_is_configured` passes throughout, because a planted import
violates the configuration rather than changing it - which is exactly the
division of labour those two tests exist to keep.

`--no-logo` suppresses import-linter's nine-line ASCII banner and nothing else;
it is the same flag `.github/workflows/ci.yml` passes. Everything below is
verbatim, exit codes included.

Both planted imports were removed immediately after their red runs and exist
neither on disk nor in git history as a tracked change; the green runs at the end
are the shipped tree.
