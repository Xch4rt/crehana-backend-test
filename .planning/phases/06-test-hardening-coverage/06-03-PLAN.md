    the tests that went red.

    Required behaviours, each with the mechanism the research settled:
    - refuse a dirty tree: `git status --porcelain -- src/` must be empty at the top, else exit 1
      with the remedy on stderr;
    - restore on interrupt: `trap 'git checkout -- src/' EXIT INT TERM`, installed BEFORE the
      first mutation;
    - apply a break: a here-doc Python one-liner doing an exact `str.replace` with an
      `assert old in s` precondition, so a drifted source line fails loudly rather than silently
      mutating nothing. No `sed -i`;
    - run the tests: `.venv/bin/pytest <the break's files> --no-cov -p no:cacheprovider`, so the
      run never rewrites `coverage.xml` (the artifact the three-way agreement depends on) nor
      poisons `.pytest_cache` with a deliberately-red result;
    - assert red: invert the exit status — a PASSING run is the script's failure, and the message
      says which break survived and against which files;
    - restore: `git checkout -- src/`, then re-assert `git status --porcelain -- src/` is empty
      before moving to the next break.

    Header comment block in the `init-env.sh` voice: what the script is for (SC-4, an evaluator can
    rerun it), the five breaks named, the POSIX/`sed -i` constraint, the fact that it mutates and
    restores `src/` and therefore refuses a dirty tree, and — stated explicitly — that it is
    deliberately in neither `make test` nor `.pre-commit-config.yaml` nor `.github/workflows/ci.yml`
    (D-09), so the normal loop stays at about ten seconds. Note that PostgreSQL must be running.

    Add a `break-check` target to the `Makefile` invoking `sh scripts/break-check.sh`, add the name
    to `.PHONY`, and give it the comment block every target in that file carries — including the

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| script → working tree | `scripts/break-check.sh` writes to `src/`, the only tool in this repository that deliberately does |
| script → developer loop | A tool that can leave the tree mutated can make the next `make test` red for an invisible reason |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-31 | Tampering | `scripts/break-check.sh` mutating `src/` | mitigate | Refuse to run unless `git status --porcelain -- src/` is empty; `trap 'git checkout -- src/' EXIT INT TERM` installed before the first mutation; re-assert a clean `src/` after each restore. Asserted by `tests/unit/test_break_check.py` in a throwaway repository |
| T-06-32 | Denial of service | The normal developer loop | mitigate | The target is in neither `make test`, `.pre-commit-config.yaml` nor `.github/workflows/ci.yml` (D-09); it runs per-break target files with `--no-cov -p no:cacheprovider` so `coverage.xml` and `.pytest_cache` are untouched |
| T-06-33 | Spoofing | Token expiry enforcement (ASVS V3) | mitigate | Break 4 is retained precisely because it found the vacuous HTTP auth suite; after 06-01's fix it must redden an HTTP test, and `make break-check` fails if it does not |
| T-06-34 | Repudiation | A break that silently mutates nothing | mitigate | Every replacement carries an `assert old in s` precondition, so a drifted source line fails loudly instead of reporting a green break |
| T-06-SC | Tampering | package-manager installs | accept | No dependency is added (D-08 declines mutmut); no install task exists |
</threat_model>
