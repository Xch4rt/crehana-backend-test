<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test suite → build verdict | A green HTTP test is what the project trusts as proof the endpoint behaves |
| API handler → database | A handler that answers correctly and persists nothing is invisible to a status assertion |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-21 | Repudiation | Status-only HTTP assertions | mitigate | Half (a) with no escape hatch, plus planted-snippet self-tests proving the taint-tracking and helper resolution still work; a 201 whose body is missing a counter is a broken contract a status assertion cannot see |
| T-06-22 | Tampering | A mutation that is answered but not persisted | mitigate | Half (b) plus the D-06 sweep: every mutation is re-read through the API, so "it was written" is a fact about the database rather than about the handler's return value |
| T-06-23 | Repudiation | The `no_reread` escape hatch becoming a blanket skip | mitigate | Three-way gating: a non-empty literal reason, a node id in `REQUIRED_NO_REREAD` edited in the same commit, and a companion test that fails when an exemption outlives its reason |
| T-06-SC | Tampering | package-manager installs | accept | No dependency is added by this phase (D-08); no install task exists |
</threat_model>
