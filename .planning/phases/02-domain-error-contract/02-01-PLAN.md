<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Persistence aggregate -> domain value object | `CompletionStats` is constructed from counts produced by a SQL aggregate in Phase 3; it trusts them and performs no validation |
| Enum member -> wire / log / SQL literal | The string form of `TaskStatus` leaves the process in JSON bodies, log lines and (Phase 3) VARCHAR columns |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-11 | Tampering | `TaskStatus` string form | mitigate | `enum.StrEnum`, not `(str, Enum)`: a test asserts `f"{TaskStatus.IN_PROGRESS}" == "in_progress"` and `json.dumps` emits the bare value, so no log line or SQL literal can ship as `TaskStatus.IN_PROGRESS` |
| T-02-12 | Elevation of Privilege | `ALLOWED_TRANSITIONS` | mitigate | The table is exhaustive over `set(TaskStatus)` and asserted so; a future status added without a transition entry raises `KeyError` at the entity lookup instead of defaulting to "anything is allowed" |
| T-02-13 | Denial of Service | `CompletionStats.percentage` | mitigate | Explicit `total == 0` branch tested; an unguarded division would raise `ZeroDivisionError` inside a Phase 4 response and surface as a 500 |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | This plan installs nothing: every import is stdlib (`collections.abc`, `dataclasses`, `enum`, `typing`). `02-RESEARCH.md` "Package Legitimacy Audit" records the phase as not-applicable, so no `[ASSUMED]`/`[SUS]` package exists to gate |
</threat_model>
