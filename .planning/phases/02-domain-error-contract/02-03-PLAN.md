test modules that read as the specification of the machine.

  entity `ClassVar` stays the single source.

  result (an explicit empty string clears the field), and apply only the over-length check.

  `@dataclass(slots=True)` and not `frozen=True`: D-01/D-03 mutate `status`, `updated_at`

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Caller-supplied strings -> entity fields | Titles, names, descriptions and emails arrive from HTTP bodies via Phase 4 schemas; the entity is the last checkpoint before persistence |
| Caller-supplied datetimes -> entity fields | `due_date` arrives from the client; `now` arrives from the `Clock` adapter. Mixing naive and aware values raises `TypeError` at comparison time |
| Status change request -> aggregate invariant | The state machine is the only thing preventing an arbitrary status write |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-18 | Tampering | `Task.change_status` | mitigate | `ALLOWED_TRANSITIONS[self.status]` membership check before any assignment, raising `InvalidStatusTransitionError`; the entity is asserted unchanged after the raise, so a rejected transition cannot half-apply |
| T-02-19 | Denial of Service | naive vs aware `datetime` comparison | mitigate | `require_utc` rejects naive values with `ValidationError` and normalises aware non-UTC ones with `astimezone(UTC)`; without it `due_date < now` raises `TypeError: can't compare offset-naive and offset-aware datetimes` inside a request and becomes a 500 |
| T-02-20 | Information Disclosure | over-length / unbounded text fields | mitigate | `require_text` / `optional_text` enforce `TITLE_MAX_LENGTH`, `DESCRIPTION_MAX_LENGTH`, `NAME_MAX_LENGTH` and `EMAIL_MAX_LENGTH` at construction, so an unbounded string never reaches the database or a log line |
| T-02-21 | Information Disclosure | `ValidationError` messages | mitigate | Messages name the field and the numeric limit taken from the `ClassVar`; they never quote the rejected value back, so a caller's payload is not echoed into logs or the problem body |
| T-02-22 | Spoofing | plaintext credentials in the domain | mitigate | `User` declares `password_hash` only; no field or parameter named `password` exists, and the entity performs no verification - hashing and verification live behind the `PasswordHasher` port (plan 02-05, Phase 5) |
| T-02-23 | Tampering | typo'd attribute assignment | mitigate | `@dataclass(slots=True)` on all three entities removes `__dict__`, so `task.statsu = ...` raises `AttributeError` instead of silently creating a shadow field |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No package is installed by this plan; the phase's "Package Legitimacy Audit" records it as not-applicable |
