B042 on the single-argument leaves - observed, plan 02-02, flake8-bugbear 26.9.9

02-RESEARCH.md Pattern 6 verified the base plus InvalidStatusTransitionError, whose
__init__ takes two parameters and forwards two positional arguments. Every leaf that
takes ONE domain object (TaskNotFoundError, TaskListNotFoundError, UserNotFoundError,
DuplicateTaskListNameError) forwards a message AND a details dict, i.e. two positional
arguments for one parameter, and B042 fires. That case never appeared in research.

The rule, read out of the checker itself (bugbear.check_for_b042):

$ .venv/bin/python -c "import bugbear, inspect; src = inspect.getsource(bugbear); i = src.find('# -1 to exclude the \`self\` argument'); print(src[i:i+430])"
            # -1 to exclude the `self` argument
            expected_arg_count = (
                len(fun.args.posonlyargs)
                + len(fun.args.args)
                - 1
                + (1 if fun.args.vararg else 0)
            )
            if expected_arg_count == 0:
                # no arguments, don't need to call super().__init__()
                return

            # Look for super().__init__()

and, further down, `if len(b.value.args) != expected_arg_count: self.add_error("B042", fun)`.

So the check counts POSITIONAL arguments only, and compares that count with the number
of declared parameters. Naming `details` as a keyword makes the counts agree without
changing a single stored value, and without an inline suppression comment - which the
plan forbids, and which would in any case hide a rule whose underlying concern
(rebuilding a subclass through pickle) is answered once by DomainError.__reduce__ and
asserted by test_domain_error_survives_pickle_and_copy.
