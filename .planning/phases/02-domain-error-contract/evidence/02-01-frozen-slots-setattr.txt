Frozen + slots dataclass: setattr on a name that is NOT a field behaves
differently on the two interpreters this project runs on. Captured while
writing tests/unit/domain/test_completion.py (plan 02-01, task 2).

Probe:
  @dataclass(frozen=True, slots=True)
  class C:
      total: int
  setattr(C(total=1), <name>, 2)

CPython 3.14.3 (developer host, .venv):
  total -> FrozenInstanceError cannot assign to field 'total'
  ratio -> TypeError super(type, obj): obj (instance of CompletionStats) is not
           an instance or subtype of type (CompletionStats)

$ docker run --rm python:3.13-slim-trixie python -c ...   (Docker/CI runtime)
  total -> FrozenInstanceError cannot assign to field 'total'
  ratio -> FrozenInstanceError cannot assign to field 'ratio'
  has __dict__: False
  slots: ('total',)

Cause: the frozen __setattr__ generated by dataclasses tests 'type(self) is cls'
before falling through to super(cls, self).__setattr__. slots=True rebuilds the
class, and on 3.14.3 the closure cell still holds the pre-slots class, so the
condition is False for a non-field name and the super() call itself raises.

Consequence: the test asserts the portable claim - the assignment is refused and
the instance has no __dict__ - instead of an interpreter-specific exception type.
A test pinned to AttributeError would have been green on the host and red in CI.

$ make docker-test   (Python 3.13, after the fix)
