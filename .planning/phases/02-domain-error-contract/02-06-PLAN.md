**ADR-021 - the DomainError base shape, and what the four handlers deliberately do not
catch.** Context: `.planning/research/ARCHITECTURE.md` Pattern 6 prescribes
`__init__(self, message, **details)`, which this repository's own flake8 rejects with B042,
and the obvious B042-clean alternatives each break something else. Options: the `**details`
signature (Rejected: fails `make lint`, and `# noqa: B042` would discard a real bug);
`super().__init__(message)` only (Rejected: also B042); a leaf subclass with its own
signature and no `__reduce__` (Rejected: it *passes* B042 and still breaks
`pickle.loads` and `copy.copy` with `AttributeError`, because `Exception.__reduce__`
rebuilds via `cls(*self.args)` - B042's heuristic gives a false pass here). Decision: one
`__init__(message, details=None)` forwarding both parameters, one `__reduce__` on the base
delegating to a module-level `_restore`, and an explicit `__str__` returning
`self.message` so the 2-tuple `args` never renders the details dict into a log line or a
wire body. Also record the status choices: a domain `ValidationError` is **422** on the
"well-formed but semantically invalid" reading - the same 422 an evaluator has already
seen from Pydantic - while an invalid status transition is **409** per D-01 and TASK-05.
Consequences: a mandatory pickle/copy round-trip test (it is also what takes the module to
100% coverage); `details` values are constrained to JSON-safe primitives so the handler
cannot fail on its own input; and `ResponseValidationError` is **not** a
`RequestValidationError` - neither is a parent of the other - so a response-model mismatch
falls through to the catch-all `Exception` handler and becomes a 500 `internal_error`.
That is the intended outcome (a response-model mismatch is a server bug, not a client
error) and is recorded here so it reads as a choice.
