Create `src/taskmanager/application/ports/__init__.py` as a zero-byte file, then the five

Each module gets a docstring in the Phase 1 voice whose "why" paragraph names a rejected
alternative:
- `repositories.py`: the alternative is repositories returning ORM rows or SQLAlchemy
  `Result` objects. These Protocols speak only in domain entities, which is what lets the
  use cases be unit-tested against in-memory fakes with no database (and is where this
  project's coverage comes from).
- `unit_of_work.py`: the alternative is injecting the three repositories separately and
  committing in a FastAPI `yield` dependency teardown. D-17 and ARC-08 put the transaction
  boundary in the use case, so the three repositories arrive bound to one transaction
  through a single async context manager.
- `security.py`: the alternative is calling PyJWT and Argon2 directly from a use case. The
  ports keep the application layer free of both, so Phase 5 swaps the library without
  touching a use case. Record why `TokenService` is `async` even though signing an HS256
  token does no I/O: D-19 makes every port async except `Clock`, and a uniform port surface
  costs nothing here while leaving room for an adapter that fetches a rotating key.
- `notifications.py`: the alternative is sending email inline from the use case; the port
  exists so Phase 5's fake-invitation adapter can be swapped and so a notifier failure is a
  decision rather than a 500.
- `clock.py`: the alternatives are a bare `Callable[[], datetime]` and putting `Clock` in
  `domain/`. D-13 fixes the call site as `clock.now()`, and a `domain -> application` import
  would be an upward import that fails the `layers` contract.

Hard constraints:
- `Protocol` bodies are `...` and nothing else. No default implementation, no docstring
  inside a method body, no `raise NotImplementedError` - "ports exist with no
  implementation" is the literal wording of roadmap success criterion 3.
- Do **not** use `@runtime_checkable`: `issubclass()` raises
  `TypeError: Protocols with non-method members don't support issubclass()` on `UnitOfWork`
  because of `tasks`/`task_lists`/`users`, and a runtime check would only prove attribute
  presence anyway. Conformance is proven by mypy plus Task 2's named tests.
- `UnitOfWork.__aenter__` returns `typing.Self`; `__aexit__` takes
  `types.TracebackType | None`.
- Imports: `collections.abc.Sequence`, `datetime`, `types.TracebackType`,
  `typing.Protocol`/`Self`, `uuid.UUID`, plus `taskmanager.domain.*`. Nothing else - no
  `fastapi`, no `starlette`, no `sqlalchemy`, and no `pydantic` (D-16 keeps the layer free
  of it even though `.importlinter` still permits it).
- Formatting: run `make format` and then `make lint`. Where black wraps a stub signature
  across lines, pycodestyle fires `E301 expected 1 blank line, found 0` on the *next* stub
  def; the fix is one blank line between **every** method of that Protocol - expected for
  `TaskRepository` (because of `list_for_task_list`), `UnitOfWork` (because of `__aexit__`)
  and `EmailNotifier` (because of `send_task_assigned`). Protocols whose methods are all
  one-liners stay packed. Iterate `make format` then `make lint` until both are clean and
  stable across two consecutive runs.

Finish with `make lint && make typecheck && make arch`.
