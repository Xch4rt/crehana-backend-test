  DomainError(Exception)                       code                        title
  ├── ValidationError                          validation_error            "Validation error"
  ├── BusinessRuleViolationError               business_rule_violation     "Business rule violated"
  │   └── InvalidStatusTransitionError         invalid_status_transition   "Invalid status transition"
  ├── NotFoundError                            not_found                   "Resource not found"
  │   ├── TaskNotFoundError                    task_not_found              "Task not found"
  │   ├── TaskListNotFoundError                task_list_not_found         "Task list not found"
  │   └── UserNotFoundError                    user_not_found              "User not found"
  ├── ConflictError                            conflict                    "Conflict"
  │   ├── DuplicateTaskListNameError           duplicate_task_list_name    "Duplicate task list name"
  │   └── EmailAlreadyRegisteredError          email_already_registered    "Email already registered"
  ├── AuthenticationError                      authentication_failed       "Authentication failed"
  └── AuthorizationError                       authorization_failed        "Authorization failed"

  DomainError itself carries code "domain_error" / title "Domain error".

  # Signatures
  DetailValue = str | int | float | bool | None
  Details = dict[str, DetailValue]

  DomainError(message: str, details: Details | None = None)
  InvalidStatusTransitionError(current: TaskStatus, requested: TaskStatus)
      -> details {"from": current.value, "to": requested.value}
  TaskNotFoundError(task_id: UUID)        -> details {"task_id": str(task_id)}
  TaskListNotFoundError(task_list_id: UUID) -> details {"task_list_id": str(task_list_id)}
  UserNotFoundError(user_id: UUID)        -> details {"user_id": str(user_id)}
  DuplicateTaskListNameError(name: str)   -> details {"field": "name", "name": name}
  EmailAlreadyRegisteredError()           -> details {"field": "email"}   # value NOT echoed
  ValidationError / BusinessRuleViolationError / NotFoundError / ConflictError /
  AuthenticationError / AuthorizationError keep the base (message, details) signature.

  # Instance attributes, set by the base __init__
  exc.message: str
  exc.details: Details        # {} when none was passed, never None

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Domain error -> problem+json body | Whatever is in `exc.details` is serialized into an HTTP response by the plan 02-04 handler, unfiltered |
| Domain error -> server log | `str(exc)` is what appears in a log line; the inherited `Exception.__str__` would render the whole `args` tuple |
| Client input -> error details | Entity validation (plan 02-03) and use cases (plan 02-05) construct these errors from caller-supplied values |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04 | Denial of Service | `DomainError.details` -> `JSONResponse` | mitigate | Two layers: the `Details = dict[str, str \| int \| float \| bool \| None]` alias makes a `UUID`/enum value a mypy error, and `test_every_error_details_payload_is_json_serialisable` calls `json.dumps` on every class's details. An unserialisable value would raise inside the error handler and turn a 409 into a 500 |
| T-02-14 | Information Disclosure | `str(exc)` leaking the details dict | mitigate | Explicit `__str__` returning `self.message`, asserted by `test_domain_error_survives_pickle_and_copy`; without it every log line and any `detail=str(exc)` would carry the structured payload |
| T-02-15 | Information Disclosure | `EmailAlreadyRegisteredError` | mitigate | `details` carries `{"field": "email"}` and never the address. Account enumeration through the 409 itself is accepted (AUTH-01 requires the 409), but the value is not echoed into the body or the logs |
| T-02-16 | Elevation of Privilege | an unmapped new error class | mitigate | `test_hierarchy_is_closed` compares a recursive `__subclasses__()` walk against a literal twelve-name set, so a class added without a status mapping fails a test instead of silently resolving to the `DomainError` default (500) |
| T-02-17 | Tampering | `fastapi.HTTPException` or an HTTP status leaking into the domain | mitigate | Grep gates assert no `fastapi`/`starlette`/`http` import and no status-code literal in `exceptions.py`; `make arch` enforces the same at package level (PC-4) |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No package is installed by this plan; `02-RESEARCH.md` "Package Legitimacy Audit" records the phase as not-applicable |
</threat_model>
