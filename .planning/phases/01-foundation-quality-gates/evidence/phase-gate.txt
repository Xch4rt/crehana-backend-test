Two conventions used in this capture
------------------------------------

1. Trailing whitespace is stripped from every captured line. This repository's
   own `trim trailing whitespace` hook runs on this file, so leaving it in
   would mean the evidence is rewritten the moment it is committed. The only
   output affected is the nine-line import-linter banner, which is elided
   below and marked as such; no line of substance is altered.

2. The D-20 attribution audit is run in two forms, raw and refined, and both
   are reported. The raw form —

       git log --all --format='%B' | grep -ciE 'co-authored-by|claude|generated with|anthropic'

   — returns 1, not 0. The single match is the SUBJECT LINE of commit 0456070,
   `docs(01-06): state the enforced layer, gate and attribution rules in
   CLAUDE.md`. That is the name of a file in this repository, not an
   attribution trailer, and history is not going to be rewritten to hide a
   filename. So the audit is refined by excluding the literal token
   `CLAUDE.md` before matching —

       git log --all --format='%B' | grep -v 'CLAUDE\.md' | grep -ciE 'co-authored-by|claude|generated with|anthropic'

   — which must return 0, AND the raw match is printed verbatim below so a
   reader can confirm for themselves that the only thing the loose pattern
   ever caught is that filename. The check is not weakened in any other way:
   all four patterns, all branches, all commit bodies, case-insensitive.
