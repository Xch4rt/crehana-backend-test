RUN 3 - THE CONTRAST: python -m importlinter.cli, same violation, exit code 0
================================================================================

This is why tests/architecture/test_layer_boundaries.py calls the Python API instead
of shelling out. The module-execution form below reports NOTHING and succeeds while
the forbidden import is still sitting in the domain. An architecture test built on it
passes forever - the worst possible outcome for a quality gate, because it looks green.

The cause: importlinter's cli module has no `if __name__ == "__main__":` guard and the
package ships no __main__.py, so `python -m` imports the module (registering the click
commands) and exits without invoking any of them.

$ .venv/bin/python -m importlinter.cli lint-imports
EXIT=0

(no output whatsoever - the blank line above is the entire result)

The related form fails loudly instead, which is at least honest, though for the wrong
reason - it never checks anything either:

================================================================================
APPENDIX - the second failure mode: a config that configures nothing
================================================================================

Everything above proves the contracts catch a bad import. It does not prove they are
loaded at all, and that is a separate, quieter way for this gate to die: import-linter's
success condition is "no broken contracts", and zero contracts satisfies it vacuously.
That is what test_every_contract_is_configured exists for, so it was worth observing too.

First, a correction to this project's own research. RESEARCH Pitfall 2 claims the trap is
writing the section header as [importlinter:contracts:layers] (plural) instead of
[importlinter:contract:layers]. Applied to all three headers, that typo changes nothing:

$ .venv/bin/lint-imports        # with [importlinter:contracts:...] x3
  Layered architecture (high to low) KEPT
  Domain is framework-free KEPT
  Application knows no web framework or ORM KEPT
  Contracts: 3 kept, 0 broken.
EXIT=0
$ .venv/bin/pytest tests/architecture -q --no-cov
2 passed
EXIT=0

The reason is in importlinter/adapters/user_options.py: the INI reader keeps every
section whose name starts with "importlinter:" and uses section_name.split(":")[-1] as
the contract id. The middle word is never inspected, so "contract", "contracts" and
anything else all work. The stated pitfall does not reproduce on import-linter 2.15.

The real trap is one level up - getting the PREFIX wrong. The tool is spelled
"import-linter" everywhere (PyPI, docs, the console script), while the section prefix is
"importlinter" with no hyphen, which makes this a genuinely easy mistake:

$ .venv/bin/lint-imports        # with [import-linter:contract:...] x3
