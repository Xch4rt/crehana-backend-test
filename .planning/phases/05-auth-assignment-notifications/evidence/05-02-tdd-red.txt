The test was first written as `assert await hasher.dummy_verify("pw") is None`.
With the port declaring `-> None`, mypy strict answers:

tests/unit/application/test_ports.py:112: error: Function does not return a value (it only ever returns None)  [func-returns-value]

That is the port comment's rule being enforced by the type checker rather than
by a convention: no caller can read this method's return at all, so a caller
cannot be tempted to branch on it. The assertion was dropped and the reason
written into the test's docstring; the runtime `is None` claim is kept in the
plan's acceptance snippet, which runs outside mypy.
