<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated form body → a credential check | `POST /auth/login` is open by definition and is where credentials arrive |
| unauthenticated JSON body → account creation | `POST /auth/register` is the other open write |
| the OpenAPI document → a client | A document that claims a route is open when it is not, or the reverse, misleads every consumer |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-04 | Information disclosure | the submitted password echoed into a 422 body | mitigate | `handle_validation_error` keeps only `loc`/`msg`/`type` — an existing property this phase depends on, verified in research and asserted over HTTP by plan 05-13 |
| T-5-06 | Information disclosure | register's 409 as an enumeration oracle | **accept** (D-23) | The 409 is required by AUTH-01 and is an oracle by construction. The route description states it plainly rather than claiming otherwise; the error carries no address; the bound is that `GET /users` already discloses every address to any authenticated caller |
| T-5-09 | Elevation of privilege | mass assignment on register | mitigate | `RegisterRequest` forbids extras (plan 05-09); the handler passes `payload.to_command()` and nothing else, so no path or header value can reach the command |
| AUTH-02 | Spoofing | a `tokenUrl` pointing nowhere, leaving Authorize broken | mitigate | Asserted from the document: the scheme's `tokenUrl` must end with the login path, which is the only automated check standing behind the manual `/docs` verification |
| AUTH-03 | Spoofing | a route shipped without a token requirement | mitigate | The partition assertion over `app.openapi()["paths"]`: every operation is either one of three named open ones or carries a `security` array |
| ADR-051 | Tampering | `HTTPException` in a new router | mitigate | `routers/auth.py` joins `REQUIRED_SCANNED_MODULES` in the commit that creates it (Pitfall 14); the AST gate refuses the import as well as the raise |
| T-5-03 | Information disclosure | a secret reaching the OpenAPI description | mitigate | The description names a procedure, not a credential; there is no seeded account and no password anywhere in the repository (D-14) |
| T-5-SC | Tampering | pip installs | accept | No package is added. `python-multipart`, which `OAuth2PasswordRequestForm` requires at **route declaration** time (Pitfall 8 — without it the whole application fails to build, not just login), is already pinned and audited |
</threat_model>
