<objective>
Close the one BLOCKER and the four warnings that Phase 5 verification and review found, and
leave the running stack healthy on a secret that is not in the repository.

The blocker: `Settings` accepts `replace-me-with-a-generated-secret` — the value published in
`.env.example`, and the value the container on this machine is running with right now — because
the only check is a 32-character floor that a 34-character placeholder clears. The verifier
forged a token offline with that string and `GET /api/v1/auth/me` returned another account's
profile with 200. `settings.py`'s own module docstring promises this cannot happen.

Purpose: make that docstring true, without costing the evaluator their one-command setup.
`cp .env.example .env` becomes `make env`, which generates a real secret into an untracked
`.env`. This amends locked decision D-15, so every place that documents the old command changes
with it.

Output: a boot-time refusal with a readable remedy, a closed algorithm set, a `make env` target
and its script, three robustness fixes (WR-01, WR-02, WR-04), one ADR, one AI_WORKFLOW entry, one
CLAUDE.md rule, and a green `make lint && make typecheck && make arch && make test`.

Out of scope, deliberately: IN-01, IN-02, IN-03 and IN-04 from `05-REVIEW.md`. Do not plan or
write them.

    WR-04, in the domain and once. Rename `_refuse_nul` to `_refuse_unstorable` and add a public
    predicate `is_storable_text(value: str) -> bool` that answers the single question "can
    PostgreSQL's text types hold this?": no NUL, and `value.encode("utf-8")` does not raise
    `UnicodeEncodeError` (which is what a lone surrogate such as `"A\ud800B"` does). The rule
    lives in the predicate and nowhere else; `_refuse_unstorable` returns early when the predicate
    says yes, and only then decides which of two messages to raise — the existing NUL wording,
    unchanged, or a new one for text that is not valid Unicode. Re-testing for NUL inside
    `_refuse_unstorable` selects wording only and can never gate the refusal, so the two cannot
    drift. `require_text` and `optional_text` keep their single call site, renamed, which closes
    the same hole for list names, task titles and every description without a second guard.

    web framework. In `Login.execute`, before the `async with self._uow` block, short-circuit when
    `not is_storable_text(command.email)`: `await self._hasher.dummy_verify(command.password)`,

    so the body is identical by construction rather than by care. Guarding before the block means
    no connection is taken out for a lookup that cannot succeed, and no `DataError` is ever
    raised, so the psycopg message carrying the submitted address never reaches a log line. Add a
    short paragraph to the module docstring in the file's existing voice: an address the database
    cannot hold is an address no account has, and it is refused on the same terms and at the same
    cost as one that merely does not exist. Do not add a length bound here — an over-long address
    is a `SELECT` parameter, not an insert, and answers 401 today; IN-01 is out of scope.

    costs a hash. Add one line after the existing `require_password` call and before
