<objective>
Make the simulated invitation visible. The runtime notifier writes one structured JSON line, and the
application configures logging so that line is actually emitted — which, verified by execution, it
is not today.

Purpose: uvicorn's `LOGGING_CONFIG` declares handlers only for the `uvicorn*` loggers; it attaches
nothing to root and leaves root at `WARNING`, so `logging.getLogger("taskmanager.notifications")
.info(...)` is dropped entirely. NOTF-02 asks for a message an evaluator can find with one `grep` in
`docker compose logs api`, and without this module there is nothing to find.
Output: `infrastructure/logging.py` and `infrastructure/notifications/logging.py`.
</objective>

    `record.getMessage()`), then merges every non-reserved attribute of `record.__dict__` — the
    fields a caller passed through `extra=` — and returns `json.dumps(payload)`. Compute the

    hard-coding a list that will drift with the standard library.

    `taskmanager` logger, sets the level, and returns early if a handler carrying a private marker
    attribute is already present. The marker is what makes it idempotent; the docstring must say
    that `create_app()` runs hundreds of times across the suite, so without it the line multiplies.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller-supplied task title → a log record | Untrusted text reaching an operator's log stream, which is a machine-parsed document |
| caller-supplied email address → a log record | The one place in this phase a user's address is written outside the database |
| application logger → container stdout | What `docker compose logs api` shows, and therefore what an evaluator reads |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-13 | Tampering | log injection through the task title or a display name | mitigate | Every field goes through `json.dumps`, which escapes newlines, so a record is one line by construction; the formatter test builds a message containing `\n` and a `{"level": "INFO"}` fragment and asserts exactly one parseable line with the injected text as a value |
| T-5-14 | Tampering | email header injection | accept (not applicable yet) | Nothing is transmitted — the adapter imports no mail library and a grep for one is an acceptance criterion. The deferral is written into the adapter docstring so the author of a future SMTP adapter meets it |
| T-5-04 | Information disclosure | a token or a password reaching the log stream | mitigate | The notifier is handed exactly three values by its port — an address, a title and an id — and no other field is logged; the 500 handler's existing record still logs only method and path |
| T-5-03 | Information disclosure | secrets becoming machine-readable now that the 500 record is JSON | accept | The package-wide handler's blast radius is named in the module docstring and recorded as an ADR in plan 05-16; the reformatted record's *content* is unchanged, only its encoding |
| T-4-xx | Repudiation | a notification that is claimed but never emitted | mitigate | uvicorn configures only `uvicorn*` loggers and leaves root at WARNING, which was verified by execution to drop the INFO line entirely; `configure_logging()` fixes it, and plan 05-15's cold-start capture shows the line in `docker compose logs api` |
| T-5-SC | Tampering | pip installs | accept | This plan installs no package and imports only the standard library (`json`, `logging`, `sys`) |
</threat_model>
