<objective>
Close the gap CONTEXT names as "a known gap, not a choice": `User` has no `full_name`, and AUTH-01
and ASGN-03 both require one. The column reaches the entity, the ORM model, the mappers and a second
Alembic revision in one vertical, together with the `tasks.assignee_id` index D-25 asks for.

entity alone breaks `user_to_entity` under mypy; adding it to the model alone makes `alembic check`
report drift. The blast radius is enumerated and taken in one plan.
Output: `User.full_name`, `UserRow.full_name`, the mapper trio, `IX_TASKS_ASSIGNEE_ID`, and
`0002_full_name_and_assignee_index.py`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller-supplied `full_name` → a stored text column | The first new text field since the WR-03 NUL fix, and it must go through the same helper |
| migration → an existing developer database | A `NOT NULL` add over rows that already exist is where a schema change breaks somebody's machine |
| model declarations → the migration chain | Drift between the two is invisible until the next deploy |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-13 | Tampering | log injection or control characters through `full_name` | mitigate | `full_name` goes through `require_text`, which refuses blank, refuses NUL (review fix WR-03) and caps at the entity's `FULL_NAME_MAX_LENGTH`; the `VARCHAR(100)` is a backstop, and a 101-character name is refused before a statement is issued |
| T-5-09 | Elevation of privilege | mass assignment of `full_name` onto someone else's row | mitigate | The entity is only reachable through a use case; no route in this plan; `apply_user_to_row` deliberately never reassigns `row.id` |
| T-3-xx | Denial of service | sequential scan on `tasks.assignee_id` for `assigned-to-me` and for every `ON DELETE SET NULL` | mitigate | `ix_tasks_assignee_id` on the model and in the revision, with the counter-argument to the file's two refused indexes written out |
| T-5-03 | Information disclosure | a credential-looking default reaching the database | accept | The transient `server_default="Unnamed"` is a display name, carries no secret, and is dropped in the same `upgrade()`; `alembic check` is the gate that proves it did not survive |
| T-4-xx | Repudiation | a schema claim that the database does not honour | mitigate | `alembic check`, the compiled-DDL constraint-name assertion (thirteen names) and a single-step downgrade/upgrade round trip against the real server |
| T-5-SC | Tampering | pip installs | accept | This plan installs no package; `requirements*.txt` unchanged |
</threat_model>
