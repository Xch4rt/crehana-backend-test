<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated caller → someone else's task assignment | The phase's new write door, exercised here over real HTTP |
| a committed write → an outbound side effect | The notification must not be able to influence what is already durable |
| two concurrent writers → one task row | The owner and the assignee are now both legitimate writers |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-12 | Information disclosure | user-existence oracle through `PUT .../assignee` | mitigate | The stranger-with-a-bad-assignee-id test compares its body against the stranger-with-a-good-one body and requires them identical once `instance` is tokenised out — a status comparison alone would miss a leak through `code` |
| T-5-11 | Information disclosure / Tampering | IDOR across the assignment routes | mitigate | Every assignee and stranger leg of D-03 is asserted, and each 403 test re-reads as the owner to confirm nothing was written before the refusal |
| T-5-17 | Tampering | lost update between the owner and the assignee | mitigate | The new two-connection case proves the second writer waits on a lock and then applies to the first's committed state; without `for_update` it goes red |
| T-5-13 | Tampering | log injection through a task title into the notification | mitigate | One case assigns a task whose title contains a newline and asserts the emitted record is still exactly one parseable JSON line |
| NOTF-03 | Denial of service | a failing notifier rolling back an assignment | mitigate | The failure test overrides the notifier provider and then **re-reads through the API**, so an implementation that swallowed the error and rolled back fails |
| T-5-04 | Information disclosure | the assignee's address reaching a place it should not | accept | The address is logged by design (D-15, NOTF-02) and is already readable by every authenticated caller through `GET /users` (D-13); no token and no credential is logged |
| ADR-054 | Repudiation | a statement count that passes because the harness short-circuited the work | mitigate | The module moves to `authenticated_client`, which runs the real actor dependency; the new first entry is named in the comment rather than silently absorbed (D-20) |
| T-5-SC | Tampering | pip installs | accept | This plan installs no package |
</threat_model>
