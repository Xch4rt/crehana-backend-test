<objective>
Write the two credential adapters Phase 2 declared ports for, and the typed container that carries
them from the composition root to the request.

Purpose: these are the two places the project's security rests on a library rather than on its own
code, and both have a documented wrong way to use them — `pwdlib.verify` with transposed arguments
silently breaks every login the moment someone swallows `UnknownHashError`, and `jwt.decode`
without a pinned `algorithms` list accepts `alg=none`. Writing them behind the existing ports, with
a behaviour table proven by test rather than by recall, is the whole of AUTH-04's library half.
Output: `PwdlibPasswordHasher`, `JwtTokenService`, `SecurityResources`.
</objective>

## Trust Boundaries

| Boundary | Description |

| attacker-supplied token → `jwt.decode` | The single most attacked surface in the phase; everything downstream trusts its result |
