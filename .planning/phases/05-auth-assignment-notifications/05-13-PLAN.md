<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous client → every authenticated route | The column of the permission model that has no credential at all |
| a forged or expired token → the actor seam | Five distinct failure modes that must be one indistinguishable answer |
| a 4xx response body → an attacker | Error bodies are the cheapest oracle in any API |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-01 | Spoofing | forged / foreign-secret / `alg=none` tokens accepted | mitigate | The parametrized unauthenticated test builds each forgery and asserts an identical 401; the tokens are constructed in the test rather than described |
| T-5-15 | Spoofing | a valid token for a user that does not exist | mitigate | One parametrized case mints a token for an unseeded `uuid4()` and asserts the same 401 — the property D-11's extra `SELECT` buys |
| T-5-04 | Information disclosure | the token or the password echoed into a body | mitigate | Explicit assertions that the bogus token string is absent from the 401 text and the submitted password is absent from both 422 texts |
| T-5-05 | Information disclosure | login enumeration | mitigate | The unknown-email and wrong-password responses are compared **body to body** with `instance` tokenised out, not merely by status |
| T-5-06 | Information disclosure | register's 409 | **accept** (D-23) | The test asserts the 409 exists (AUTH-01 requires it) and that its body names no address. Recorded as an accepted, bounded oracle in plan 05-16's ADR — never as mitigated |
| T-5-08 | Information disclosure | `password_hash` reaching a response | mitigate | Member-list assertions in declaration order on every 2xx body, which a renamed field cannot pass |
| AUTH-03 | Spoofing | a route answering without a token | mitigate | Every 401 leg is measured through `authenticated_client`, which does not override the actor dependency — the whole reason the second fixture exists (D-20) |
| T-5-SC | Tampering | pip installs | accept | This plan installs no package and adds no test dependency; `freezegun` is explicitly not used and a grep for it is an acceptance criterion |
</threat_model>
