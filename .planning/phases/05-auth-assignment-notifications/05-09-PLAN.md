<objective>
Type every new HTTP boundary this phase opens, and prove the two things those boundaries refuse by
having no field for them.

assignment (T-5-09, T-5-10). The password is the first value in this project that must be typed at
the boundary and then deliberately *stripped of its type* before crossing into the application
layer, and the register response is the first one whose danger is a field it must never gain.

set.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untrusted JSON body → a typed model | The only place mass assignment can be closed, and it is closed by `extra="forbid"` rather than by a whitelist someone maintains |
| a result DTO → a serialised response | A field added to `UserResult` must not become public by default |
| a credential → anything that can print it | `repr`, logs and error bodies are three separate ways a password escapes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-09 | Elevation of privilege | mass assignment on register (`id`, `created_at`, a role) | mitigate | `extra="forbid"` on `RegisterRequest`, asserted as exactly one `extra_forbidden` error at the offending key; the command has only three fields, so nothing else can travel |
| T-5-10 | Tampering | `assignee_id` smuggled through `POST .../tasks` or the generic `PATCH` | mitigate | Neither model declares the field and both forbid extras; two new tests assert exactly one `extra_forbidden` error at `(assignee_id,)`, the same "proven by absence" form 04-07 used for `status` |
| T-5-04 | Information disclosure | the password echoed into a body, a log or a traceback | mitigate | `SecretStr` masks in `repr`, `str()`, `model_dump()` and `model_dump_json()` (verified); `to_command` unwraps it exactly once, at the boundary; the existing validation handler keeps only `loc`/`msg`/`type` so a submitted value never reaches a 422 body |
| T-5-08 | Information disclosure | `password_hash` reaching a response | mitigate | Neither response model declares it, and both member lists are asserted in declaration order rather than with a per-key absence check |
| ADR-051 | Tampering | a new presentation module raising or importing `HTTPException` | mitigate | Both new modules join `REQUIRED_SCANNED_MODULES` in the commit that creates them, so the AST gate's non-vacuity guard asserts they must be scanned (Pitfall 14) |
| T-5-SC | Tampering | pip installs | accept | This plan installs no package; `email-validator` backing `EmailStr` is already pinned and was re-checked in `05-RESEARCH.md` § Package Legitimacy Audit |
</threat_model>
