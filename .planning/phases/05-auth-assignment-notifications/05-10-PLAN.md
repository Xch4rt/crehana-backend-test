order where each commit leaves the tree green.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `Authorization` header → an identity | Every authorization decision in the project descends from this one parse |
| `app.state` → a typed adapter | An untyped read here is an implicit `Any` that silently disables type checking downstream |
| container startup → database contents | A seeded account with a known identifier is a shipped credential-shaped artefact |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-15 | Spoofing | a token outliving its user row | mitigate | `AuthenticateActor` confirms the row on **every** request (D-11); the cost is one indexed `SELECT`, re-measured deliberately in plan 05-13's `test_statements.py` |
| T-5-01 | Spoofing | a forged or `alg=none` token accepted at the seam | mitigate | The seam names no algorithm and no library; the decode is reachable only through `TokenService`, whose adapter pins `algorithms` from settings (plan 05-05) |
| T-5-04 | Information disclosure | a rejected token echoed into the 401 body | mitigate | One fixed `AuthenticationError` message for every failure mode; the evidence capture records the live body so the claim is checkable rather than asserted |
| AUTH-03 | Spoofing | a route reachable without a token | mitigate | `CurrentActor` is on every handler and its provider now raises on a falsy token; the anonymous column of plan 05-15's matrix covers all 19 routes |
| ADR-051 | Tampering | `HTTPException` re-entering presentation through `OAuth2PasswordBearer` | mitigate | `auto_error=False`, asserted by a grep and by the AST gate, which covers all of `presentation/api` after review fix WR-05 including aliased and star imports |
| T-5-03 | Information disclosure | a shipped demo account | mitigate | `DEMO_USER_ID` and the entrypoint seed are deleted; the stack ships with zero users and no password exists anywhere in the repository (D-14). The already-seeded row on developer volumes cannot become a live account: `"!"` is not an Argon2 hash and plan 05-05's adapter turns that into `False` |
| Pitfall 4 | Denial of service | the actor dependency dialling the real DSN under test | mitigate | The unit of work arrives through `Depends(get_uow)`; a grep for `get_uow(request)` in `actor.py` printing `0` is an acceptance criterion |
| T-5-SC | Tampering | pip installs | accept | This plan installs no package; `python-multipart`, needed the moment `OAuth2PasswordRequestForm` appears in plan 05-11, is already pinned and audited |
</threat_model>
